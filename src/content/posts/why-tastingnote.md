## 시작은 포장지 한 줄

원두 봉투에는 보통 이런 줄이 있다. "블루베리, 자스민, 꿀."

마셔 보면 어떤 건 느껴지고, 어떤 건 끝까지 모르겠다. 그런데 기록을 해도 남는 건 "맛있었다"나 "별로였다" 정도다. 적힌 노트 중 무엇을 실제로 느꼈는지는 어디에도 남지 않는다.

## 만들려는 것

한 문장으로 줄이면 이렇다.

> 포장지에 적힌 노트를 내가 실제로 느꼈는지 기록하고, 기록이 쌓이면 내가 잘 느끼는 향과 못 느끼는 향을 보여 주는 앱.

쓰는 흐름은 세 단계다.

1. 포장지를 찍으면 원두 이름과 노트가 채워진다.
2. 노트를 하나씩 보면서 "느껴짐 / 계열까지는 느껴짐 / 안 느껴짐" 중 하나를 누른다.
3. 기록이 쌓이면 향미 계열별로 "적힌 노트를 몇 % 느꼈는지"가 보인다.

만족도(별로 / 보통 / 좋음)는 따로 남긴다. "좋았다"와 "느껴졌다"는 다른 이야기라서다. 블루베리를 못 느꼈어도 그 커피가 좋을 수 있다.

## 정해 둔 원칙

**서버도, 계정도 없이 시작한다.** 기록은 휴대폰에만 저장하고, 백업은 JSON 파일로 내보낸다. 혼자 쓰는 단계에서 서버는 기능보다 운영 부담이 더 크다.

**향미 분류는 내가 만들지 않는다.** SCA(Specialty Coffee Association)의 Coffee Taster's Flavor Wheel을 기준으로 삼았다. 9개 계열 중 결점을 뜻하는 계열을 빼고 8개를 쓰고, 그 아래에 국내 포장지에 자주 나오는 세부 노트 80개를 두었다.

**이름을 몰라도 고를 수 있게 한다.** 계열은 화면에서 이름 대신 색으로만 보여 준다. 노트 이름을 알면 검색하고, 모르면 느낀 향에 가까운 색에서 시작해 좁혀 가면 된다.

**포장지 읽기는 AI보다 규칙이 먼저다.** 휴대폰 안에서 글자를 읽고(OCR), 향미 사전과 규칙으로 노트를 뽑는다. 비용이 들지 않고 사진이 밖으로 나가지 않는다. AI는 규칙이 실패하는 경우가 충분히 쌓였을 때의 다음 후보로 남겨 두었다.

## 어떻게 만들어 가나

나는 Java와 Spring Boot로 일하는 백엔드 개발자이고, Android는 처음이다.

그래서 AI(Claude)와 함께 만들기로 했다. 다만 AI가 짠 코드를 받아서 읽고 이해하는 방식은 아니다. 미션을 하나씩 받아 직접 만들고, 휴대폰에서 돌려 본 뒤, 질문에 답하며 이해했는지 확인한다. 퀴즈를 하나씩 풀며 다음 판으로 넘어가는 게임에 가깝다. 한 단계마다 이 순서로 간다.

1. **설명:** 이번에 다룰 Android 개념을 Spring Boot와 비교해서 듣는다.
2. **미션:** 빈칸을 채우며 내가 직접 구현한다. 미션은 한 번에 하나씩만 받는다.
3. **실행:** 내 휴대폰(Galaxy S25)에서 돌려 본다.
4. **질문:** 방금 만든 것이 왜 그렇게 동작하는지 답한다.
5. **검토:** 함께 코드를 본다.

> [!NOTE]
> 처음에는 코드를 보기 전에 동작을 예측하는 질문을 먼저 받았다. 그런데 처음 보는 개념은 해 보기도 전에 맞히기가 어려웠고, 답이 추측이 됐다. 그래서 1단계 중간에 질문을 미션 뒤로 옮겼다.

0단계에서 실제로 나눈 장면 하나를 옮기면 이렇다.

> **설명.** Spring Boot는 내가 쓴 `main()`에서 실행이 시작된다. Android 앱에는 직접 쓰는 `main()`이 없다.
>
> **질문.** 그럼 아이콘을 눌렀을 때 내 코드 중 무엇이 가장 먼저 실행될까? 새 프로젝트의 `MainActivity.kt`에서 `main()`에 해당하는 함수를 하나 골라 보라는 질문을 받았다.
>
> ```kotlin
> class MainActivity : ComponentActivity() {
>     override fun onCreate(savedInstanceState: Bundle?) {
>         super.onCreate(savedInstanceState)
>         enableEdgeToEdge()
>         setContent {
>             // 화면에 "Hello Android!"를 그리는 Compose 코드 (생략)
>         }
>     }
> }
> ```
>
> **내 답.** `onCreate`.
>
> **풀이.** 맞았다. 아이콘을 누르면 Android OS가 앱을 띄우고, `AndroidManifest.xml`에 시작 화면으로 등록된 `MainActivity`를 직접 만든 뒤 `onCreate()`를 부른다. Spring에서 Controller 메서드를 내가 직접 호출하지 않는 것과 같다. 내가 부르는 것이 아니라, 불려진다.

처음 나오는 종류의 코드는 내가 직접 쓰고, 같은 종류의 반복은 AI에게 맡긴다.

전체는 9단계로 나눴다.

| 단계 | 내용 |
|---|---|
| 0 | Android Studio 설치, 빈 프로젝트를 휴대폰에서 실행, 블로그 만들기 |
| 1 | 프로젝트 구조와 Compose 기초 |
| 2 | 로컬 DB(Room)와 향미 사전 넣기 |
| 3 | 화면 이동 |
| 4 | 향미 고르기 |
| 5 | 체감 기록 흐름 |
| 6 | 카메라와 글자 읽기 |
| 7 | 프로필 집계 |
| 8 | 백업 |

## 0단계를 끝내며

오늘 0단계를 끝냈다. Android Studio를 설치하고, 빈 프로젝트를 만들어 휴대폰에 "Hello Android!"를 띄웠다. 그리고 이 블로그를 만들었다.

프로그래밍을 배울 때마다 늘 보는 간단한 Hello World였지만, 이번에는 평소와 다르게 느껴졌다. 요즘은 AI가 짠 코드를 읽으며 이해하는 식으로 작업할 때가 많았는데, 이번처럼 하면 프로젝트를 재미있게 해 나갈 수 있겠다는 느낌이 들었다.
